## One-ticket fix loop (no cosmetic changes before trustworthiness)

1. **Reproduce:** record action, expected/observed result, host ID, project/chat ID, direct/linked, device, OS, binary/JS version, and exact failure. Use disposable desktop content for mutations.
2. **Trace:** inspect mobile control → provider → command adapter → auth/grant → desktop handler → actual persisted desktop state. Distinguish accepted from completed and independently confirmed.
3. **Patch narrowly:** preserve the largely untracked workspaces, unsent content and security grants. Address state races and interruptions without automatic replay of uncertain mutations.
4. **Regress:** red-before-green focused test, full `npm run test`, `npm run typecheck`, `npm run lint`; `npx expo-doctor` when dependencies/config change. Never call a failing full suite green.
5. **Replay:** on the current native build and the other transport, perform the identical success/rejection/slow/offline/host-switch/restart scenario; independently read the desktop before/after result.
6. **Record five distinct marks:** **S** source traced/fixed, **T** automated tests, **N** native interaction, **H** desktop effect, **P** signed/physical. Each requires evidence; screenshot-only and source-only work stays open.

### Action-test matrix (apply to each eligible command)

| Variant | Requirement |
| --- | --- |
| Expected | Exact destination, result, persistent host effect and intuitive feedback |
| Unavailable/rejected | Clear reason, usable retry, no draft loss or success claim |
| Slow/double tap | Single mutation attempt, immediate busy/disabled state, no lost edits |
| Host/project/chat A→B→A | Old response cannot change new selection, dismiss new screen, or clear new draft |
| Disconnect/background/force quit | Recover stream, reconcile pending/uncertain actions and preserve drafts |
| Revoked/expired auth | Fail closed, surface re-pairing, do not broaden desktop permissions |
| Large data/long output | Stable scroll, visible stop affordance, controlled memory and retained input |

### UI/UX acceptance budgets (targets, not measurements)

- Tap and press-state feedback: visible within **100 ms** at p95, including during network delays; never block input while awaiting a host before showing progress.
- Local navigation/sheet presentation: proposed **≤350 ms p95** without a network dependency; the original device and action must be captured in ≥30 runs.
- Stream presentation: target **≤100 ms p95** between receiving a delta on-device and showing it, measured separately from backend processing and network latency.
- Sustained feed scrolling: aim for **≥95%** frames within each device's refresh budget; record 60 Hz/120 Hz separately and investigate long-task stalls.
- No clipped essential control or keyboard-hidden Send/Stop in any required window; 44×44-point minimum targets where practicable; readable enlarged text, appropriate VoiceOver labels/focus and reduced-motion behavior.
- A target failure becomes a ticket with captured timing trace and device; these are proposed budgets and **none have been demonstrated** in this release.
