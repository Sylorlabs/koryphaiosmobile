## Fix-as-you-go protocol

1. Reproduce a defect in the smallest real flow possible; record actual device, native binary and JS/desktop versions, selected host/project/chat, direct/linked transport, expected/actual effect, and screenshot/log when allowed.
2. Trace the UI handler through provider, adapter, transport, desktop API and persisted host state. Avoid guessed causes; establish whether a command was accepted, rejected or acknowledged without authoritative confirmation.
3. Apply a minimal safe repair and a meaningful regression (state race, interruption, failure and cross-host selection, where applicable). Preserve unrelated working-tree changes and user data.
4. Run focused tests and full checks. A subsequent fix must not inherit an old green baseline. Record `S`, `T`, `N`, `H`, `P` separately per defect.
5. Replay the exact scenario on current installed native build, then inspect actual desktop state before and after; repeat on the other transport and another size class where relevant. Verify no repeated mutation on retries.
6. For UI/UX, capture a **fresh** route/interaction sequence on the current build, audit hierarchy, tap area, scrolling, keyboard, safe area, error/empty/loading, Dynamic Type, VoiceOver and perceived response, then fix/replay failures. Older screenshots are evidence only for their dates.
7. Measure latency/frame/memory behavior after correctness; use p50/p95 and a 60-minute soak, record regressions and remedy. Consider the release ready only when every P0 has full evidence and each required native/host/physical gate is explicit.
