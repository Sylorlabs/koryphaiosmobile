## Non-negotiable acceptance rules

1. **No lost work:** unsent drafts, attachments, task text, workflow evidence, title edits, and review responses survive navigation, network interruptions, race conditions, and app restarts.
2. **Correct destination:** every mutation belongs to the intended host, project, chat, agent, workflow, and prompt revision. A stale response can never alter a newer selection.
3. **Observed effects:** accepted network commands show pending/uncertain until independently reconciled against authoritative desktop state. No speculative success or automatic replay of uncertain mutations.
4. **Controllable streaming:** create, select, send, incremental output, cancel/stop, reconnect, and recover function in both direct and linked transport modes, with the actual desktop state checked at every transition.
5. **Complete control:** mobile supports every desktop capability explicitly marked in the agreed parity inventory; unsupported desktop-only features have visible scope limitations rather than silent no-ops.
6. **Native quality:** keyboard, safe areas, touches, accessibility, dark/light modes, narrow screens, large text, rotation, split view, and responsive feedback work on eligible iPhones and iPads.
7. **Verifiable release:** every P0 passes on a controlled desktop and native iOS build; device and performance gates have recorded evidence; production distribution must be tested separately.

## Continuous repair protocol

Work in narrow vertical slices and preserve the current untracked workspace. For each item: establish the desktop behavior and mobile expectation; reproduce on a controlled fixture; capture the observable failure; assign P0/P1/P2; correct the smallest viable layer; add a regression testing the failed behavior; run focused tests followed by the full project check; perform native-to-desktop validation; update its status and evidence. Mark **fixed (source)**, **tested (automated)**, **observed (native)**, and **confirmed (desktop)** separately. If an external state change cannot be verified, leave the gate open.

Do not run destructive tests against existing user data. For delete, rewind, abandon, unlink, and revoke, use disposable hosts and fixtures with known contents. Do not repeat operations previously refused by safety/permission review without fresh authorization.

### UX and performance targets (initial, measurable)

- Interactive feedback after a tap should appear within ~100 ms; remote actions should show immediate pending feedback and update on acknowledgment/authoritative state.
- For at least 30 successful samples of each key operation, record median and p95 times separately for tap feedback, first streamed output, stop acknowledgment, screen changes and reconnect. Set hard budgets after observing the controlled-host baseline.
- Test a 60-minute mixed session with streaming, screen transitions, host switches, background/foreground cycles and transient disconnections. Log app crashes, dropped stream chunks, memory growth and unsolicited mutations.
- No horizontal overflow, clipped critical controls, keyboard-covered composer, dead taps, inaccessible decisions, or unannounced destructive action on tested configurations.
